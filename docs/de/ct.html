Computational Thinking

Probleme strukturieren und zerlegen

Computational Thinking ist die Faehigkeit, Probleme so zu strukturieren, dass sie mit automatisierten Prozessen loesbar werden. Es geht nicht um Programmieren, sondern um eine Denkweise: Wie zerlege ich ein komplexes Problem in handhabbare Teile? Welche Muster erkenne ich? Was kann ich abstrahieren?

Theorie Uebungen Vertiefung Ressourcen

Theorie

Kernpunkte

  • Computational Thinking ist eine Denkweise, keine Programmiersprache
  • Die vier Saeulen: Dekomposition, Mustererkennung, Abstraktion, Algorithmus
  • Jede Saeule ist fuer sich wertvoll, auch ohne Code zu schreiben
  • LLMs verstaerken Ihre Denkarbeit - sie ersetzen sie nicht
  • Strukturiertes Denken fuehrt zu besseren Prompts und besseren Ergebnissen

Konzepte

Dekomposition

Ein komplexes Problem in kleinere, handhabbare Teile zerlegen. Jeder Teil wird separat loesbar.

Mustererkennung

Wiederkehrende Strukturen identifizieren. Was ist hier aehnlich wie bei anderen Problemen?

Abstraktion

Vom konkreten Fall zum allgemeinen Prinzip. Was ist das Wesentliche?

Algorithmus

Eine Schritt-fuer-Schritt-Anleitung zur Loesung. Praezise, wiederholbar, ueberpruefbar.

Iteration

Wiederholung eines Prozesses mit schrittweiser Verfeinerung. Test, Feedback, Anpassung.

Bedingte Logik

Entscheidungen basierend auf Bedingungen: "Wenn X, dann Y, sonst Z"

Die vier Saeulen im Detail

Saeule 1

Dekomposition

Komplexe Probleme erscheinen oft unloesbar, weil wir sie als Ganzes betrachten. Dekomposition bedeutet, sie in Teilprobleme zu zerlegen.

Beispiel: "Erstelle eine Bibliografie aus meinen Notizen" wird zu: Notizen einlesen, Felder extrahieren, Daten strukturieren, Format generieren.

Saeule 2

Mustererkennung

Wenn Sie ein Problem loesen, fragen Sie sich: Wo habe ich aehnliches schon gesehen? Muster zu erkennen spart Arbeit.

Beispiel: "CSV zusammenfuehren" und "Excel zusammenfuehren" folgen demselben Muster: Dateien finden, einlesen, pruefen, zusammenfuegen, speichern.

Saeule 3

Abstraktion

Sich auf das Wesentliche konzentrieren und Details ignorieren. Was ist die Essenz des Problems?

Beispiel: Ob Bilder, Texte oder Datenbanken - das abstrakte Problem ist oft: "Transformation von A zu B nach Regeln R".

Saeule 4

Algorithmus

Eine praezise Handlungsanweisung. So klar, dass jemand (oder etwas) sie ohne Rueckfragen ausfuehren kann.

Schlecht: "Sortiere die Dateien"
Gut: "Fuer jede Datei: Lies Datum, erstelle Ordner YYYY-MM, verschiebe."

Uebungen

CT-1

Problem zerlegen

Ueben Sie Dekomposition an einem konkreten Problem.

Lernziele: Komplexes Problem in Teilprobleme zerlegen, Abhaengigkeiten erkennen, praezise Teilaufgaben formulieren.

Szenario: 500 gescannte Archivdokumente (JPG). Ziel: OCR, nach Datum sortieren, durchsuchbare Uebersicht erstellen.

Aufgabe: Waehlen Sie ein Problem aus Ihrer Arbeit. Zerlegen Sie es in mindestens 5 Teilprobleme. Notieren Sie die Abhaengigkeiten.

CT-2

Algorithmus formulieren

Eine praezise Handlungsanweisung entwickeln.

Lernziele: Vage Beschreibungen in praezise Schritte uebersetzen, bedingte Logik formulieren, Grenzfaelle antizipieren.

Szenario: Alle Bilder im Ordner nach Aufnahmedatum sortieren.

Aufgabe: Schreiben Sie einen Algorithmus fuer: "Alle PDFs in einem Ordner nach der ersten Seite benennen". Beruecksichtigen Sie Grenzfaelle.

CT-3

Muster erkennen und abstrahieren

Von konkreten Faellen zu allgemeinen Loesungen.

Lernziele: Gemeinsame Strukturen in verschiedenen Problemen erkennen, abstrakte Problemklassen identifizieren.

Beobachtung: "Namen grossschreiben", "Datumsformat aendern", "Waehrung umrechnen" - alle folgen dem Muster: Spalte X transformieren mit Funktion F.

Aufgabe: Identifizieren Sie drei Aufgaben aus Ihrer Arbeit, die demselben abstrakten Muster folgen.

Vertiefung

CT und LLMs: Warum es zusammengehoert

Computational Thinking ist die Grundlage fuer effektive LLM-Nutzung:

Dekomposition

Macht Prompts fokussierter - ein Problem pro Anfrage

Mustererkennung

Hilft, erfolgreiche Prompts wiederzuverwenden

Abstraktion

Ermoeglicht Transfer zwischen Domains

Algorithmen

Fuehren zu praeziseren Spezifikationen

Haeufige Denkfehler

Zu frueh ins Detail

Loesung beginnen, bevor das Problem klar ist. Erst strukturieren, dann loesen.

Alles auf einmal

Das gesamte Problem in einem Prompt. Besser: Schritt fuer Schritt.

Muster uebersehen

"Das ist komplett anders" - oft sind nur die Details anders, die Struktur ist gleich.

Keine Iteration

Erster Versuch muss perfekt sein. Besser: Schnell anfangen, iterativ verbessern.

CT in der Praxis

Problem: "Ich muss 200 Aufsaetze nach Thema kategorisieren."

  1. Dekomposition: Was sind die Kategorien? Was ist der Input (PDF, Text)? Was ist der Output? Wie wird kategorisiert (Titel, Abstract)?
  2. Mustererkennung: Das ist ein Klassifikationsproblem - wie Emails sortieren oder Bilder taggen.
  3. Abstraktion: Kern = Textklassifikation: Input-Text, Analyse, Kategorie-Label
  4. Algorithmus: Fuer jeden Aufsatz: Abstract extrahieren, an LLM senden, Ergebnis speichern, bei Unsicherheit markieren.
