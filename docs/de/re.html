Requirement Engineering

Anforderungen praezise formulieren

Requirement Engineering bezeichnet die systematische Formulierung von Anforderungen. Fuer die Arbeit mit LLMs ist das entscheidend, weil ein Prompt funktional ein Requirements-Dokument ist. Wer praezise Anforderungen formulieren kann, schreibt bessere Prompts.

Theorie Uebungen Vertiefung Ressourcen

Theorie

Kernpunkte

  • Ein Prompt ist funktional ein Requirements-Dokument
  • User Stories sind niedrigschwelliger als formale Spezifikationen
  • LLMs raten bei vagen Anforderungen - sie fuellen Luecken mit Annahmen
  • Akzeptanzkriterien definieren, bevor Code generiert wird
  • Grenzfaelle und Ausnahmen antizipieren
  • Das LLM kann nur liefern, was Sie spezifizieren

Konzepte

User Story

Leichtgewichtiges Anforderungsformat: "Als [Rolle] moechte ich [Funktion], damit [Nutzen]"

INVEST-Kriterien

Gute Anforderungen sind: Independent, Negotiable, Valuable, Estimable, Small, Testable

Kernfragen

Was tun? Was nicht? Eingabe? Ausgabe? Woran erkenne ich Erfolg?

Funktionale Anforderung

Was das System tun soll (Eingabe, Verarbeitung, Ausgabe)

Akzeptanzkriterium

Messbarer Massstab, ob eine Anforderung erfuellt ist

Grenzfall

Extreme oder ungewoehnliche Eingaben, die getestet werden muessen

Die fuenf Kernfragen

Bevor Sie ein LLM ansprechen, beantworten Sie diese Fragen:

Frage 1

Was soll es tun?

Die Hauptfunktion in einem Satz.

Frage 2

Was soll es nicht tun?

Explizite Abgrenzungen.

Frage 3

Was ist die Eingabe?

Format, Quelle, Beispiele.

Frage 4

Was ist die Ausgabe?

Format, Ziel, Beispiele.

Frage 5

Woran erkenne ich Erfolg?

Messbare Kriterien.

User Stories fuer Prompts

Das User-Story-Format aus der Softwareentwicklung eignet sich hervorragend fuer Prompts:

"Als [WER bin ich / meine Rolle]
moechte ich [WAS soll passieren]
damit [WARUM / welchen Nutzen habe ich]"

Beispiel: "Als Historikerin moechte ich eine CSV-Datei mit Archivdaten in eine formatierte Bibliografie umwandeln, damit ich sie direkt in meine Publikation uebernehmen kann."

Uebungen

RE-1

User Stories schreiben

Anforderungen im User-Story-Format formulieren, bevor Sie prompten.

Lernziele: Das User-Story-Format anwenden, Akzeptanzkriterien definieren, Abgrenzungen explizit machen.

Szenario: Sie moechten ein Tool, das Ihre Bibliografie verwaltet.

Aufgabe: Schreiben Sie: 1) Eine User Story, 2) Eingabe und Ausgabe, 3) Drei Akzeptanzkriterien, 4) Zwei Abgrenzungen (Was soll es nicht tun?).

RE-2

Akzeptanzkriterien testen

Code systematisch gegen definierte Kriterien pruefen.

Lernziele: Testfaelle aus Anforderungen ableiten, systematisch Grenzfaelle durchspielen, Abweichungen dokumentieren.

Aufgabe: Nehmen Sie den generierten Code aus RE-1 und testen Sie ihn gegen Ihre Akzeptanzkriterien. Erstellen Sie eine Checkliste und pruefen Sie jeden Punkt.

Vertiefung

INVEST-Kriterien fuer Prompts

Die INVEST-Kriterien helfen, gute Anforderungen zu schreiben:

Independent

Unabhaengig. Eine Anfrage pro Prompt. Nicht: "Mach A und dann B und C".

Negotiable

Verhandelbar. Details koennen angepasst werden. Das LLM kann Rueckfragen stellen.

Valuable

Wertvoll. Jede Anforderung liefert konkreten Nutzen.

Estimable

Schaetzbar. Sie koennen einschaetzen, ob es in einem Prompt loesbar ist.

Small

Klein. Eine ueberschaubare Aufgabe. Komplexes in Teile zerlegen.

Testable

Testbar. Sie wissen vorher, wie Sie pruefen, ob es funktioniert.

Typische Fehler bei Anforderungen

"Es soll gut aussehen"

Was bedeutet "gut"? Konkretisieren!

"Wie bei X"

Das LLM kennt X vielleicht nicht oder anders.

Implizite Annahmen

"Natuerlich soll es auch Y koennen" - nein, nicht natuerlich.

Keine Grenzfaelle

Was bei leerer Eingabe? Bei Sonderzeichen?
