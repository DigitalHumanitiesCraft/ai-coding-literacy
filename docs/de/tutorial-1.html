Workshop Tutorial

Einfuehrung

LLM nutzen, Daten explorieren, Webseite erstellen

In diesem Tutorial lernen Sie den grundlegenden Workflow: Von einer Excel-Datei ueber das LLM bis zur funktionierenden Webseite. Sie arbeiten mit echten Museumsdaten und erleben, wie LLM-gestuetztes Programmieren in der Praxis funktioniert.

Downloads fuer dieses Tutorial

workshop_objekte.csv workshop_objekte.json
Loesung: analyse.py Loesung: csv_to_json.py Loesung: Webseite

Was Sie in diesem Tutorial lernen

Dieses Tutorial fuehrt Sie durch den gesamten Prozess: Sie starten mit einer Excel-Datei mit Museumsobjekten, nutzen ein LLM um die Daten zu verstehen, und erstellen am Ende eine einfache Webseite, die diese Daten anzeigt.

Der Datensatz stammt aus dem Hans Gross Kriminalmuseum in Graz. Er enthaelt 25 Objekte mit Informationen wie Titel, Datierung, Typ und Beschreibung. Die Daten sind bewusst nicht perfekt: Es gibt fehlende Werte, unterschiedliche Datumsformate und gemischte Qualitaetsstufen. Das ist realistisch fuer Museumsarbeit.

CT

Computational Thinking

Bevor Sie mit dem LLM arbeiten, hilft es, das Problem zu zerlegen. Was wollen Sie erreichen? Der Weg von der Excel-Datei zur Webseite hat mehrere Teilschritte: Daten verstehen, Daten umwandeln, Webseite erstellen, testen. Jeder Schritt wird zu einem eigenen Prompt.

Wing, J. (2006). Computational Thinking. CACM 49(3).

Teil 1: Das LLM kennenlernen

Ein Large Language Model ist ein statistisches Modell, das auf grossen Textmengen trainiert wurde. Es kann Code generieren, erklaeren und verbessern. Aber es "versteht" nicht wirklich. Es erzeugt plausible Fortsetzungen basierend auf Mustern.

Fuer dieses Tutorial koennen Sie Claude, ChatGPT oder ein anderes LLM verwenden. Oeffnen Sie das Chat-Interface und laden Sie die heruntergeladene CSV-Datei hoch.

1

Datei hochladen und explorieren

Laden Sie workshop_objekte.csv in das LLM-Chat hoch und geben Sie folgenden Prompt ein: 

Analysiere diese CSV-Datei Schritt fuer Schritt:
1. Welche Spalten gibt es?
2. Wie viele Zeilen hat die Datei?
3. Gibt es fehlende Werte?
4. Zeige mir 3 Beispielzeilen.

Beobachten Sie die Antwort. Das LLM wird die Struktur beschreiben und vielleicht Python-Code ausfuehren, um die Datei zu analysieren. Manche LLMs zeigen den Code, manche nur das Ergebnis.

So sollte die Antwort aussehen

Das LLM sollte Ihnen etwa Folgendes mitteilen:

Spalten: pid, title, objectClass, dateText, year, description, qualityScore
Zeilen: 25 Objekte
Fehlende Werte: year hat 3 leere Eintraege
Beispiele: Revolver Lefaucheux (1870), Einbruchswerkzeug (1920)...

Falls die Antwort stark abweicht, pruefen Sie ob die CSV-Datei korrekt hochgeladen wurde.

CE

Context Engineering

Die Qualitaet der LLM-Antwort haengt stark vom Kontext ab. Indem Sie die Datei hochladen, geben Sie dem LLM den noetigen Kontext. Ohne die Datei koennte es nur raten. Mit der Datei kann es konkret arbeiten.

Je mehr relevanten Kontext Sie bereitstellen, desto besser die Ergebnisse. Aber zu viel Kontext kann auch verwirren (Lost in the Middle-Effekt).

Liu et al. (2024). Lost in the Middle. TACL.

Teil 2: Daten verstehen

Bevor Sie Code generieren lassen, sollten Sie Ihre Daten verstehen. Die CSV-Datei enthaelt folgende Spalten:

  • pid - Persistente Objekt-ID
  • title - Titel des Objekts
  • objectClass - Kategorie (Waffen, Dokumente, etc.)
  • dateText - Datierungstext
  • year - Extrahiertes Jahr (numerisch)
  • description - Beschreibungstext
  • qualityScore - Datenqualitaet (0.25-1.0)
2

Datenqualitaet pruefen

Lassen Sie das LLM die Datenqualitaet analysieren: 

Pruefe die Datenqualitaet:
1. Wie viele Objekte haben year = null?
2. Welche objectClass-Werte gibt es und wie oft?
3. Was ist der Durchschnitt von qualityScore?
4. Gibt es auffaellige Muster oder Probleme?

Das LLM wird wahrscheinlich pandas verwenden, um diese Fragen zu beantworten. pandas ist eine Bibliothek fuer Datenanalyse in Python.

So sollte die Antwort aussehen

Erwartete Ergebnisse:

1. Objekte ohne year: 3 von 25
2. objectClass-Verteilung:
   - Waffen: 8
   - Dokumente: 6
   - Werkzeuge: 5
   - Sonstiges: 6
3. Durchschnitt qualityScore: ca. 0.7
4. Muster: Aeltere Objekte haben oft schlechtere Qualitaet
RE

Requirement Engineering

Praezise Fragen fuehren zu praezisen Antworten. Der Prompt oben hat vier konkrete Teilfragen. Das ist besser als "Analysiere die Datenqualitaet" - denn das LLM muss dann raten, was Sie wissen wollen.

Formulieren Sie Anforderungen so, dass Sie pruefen koennen, ob sie erfuellt wurden. "Zeige alle Objekte ohne Jahr" ist pruefbar. "Mach die Daten besser" ist es nicht.

Lucassen et al. (2016). User Stories in Practice. RE.

Teil 3: Python lokal ausfuehren

Warum lokal ausfuehren?

Das LLM fuehrt Code in einer Sandbox aus - einer isolierten Umgebung, die nach der Sitzung verschwindet. Fuer echte Projekte brauchen Sie lokale Ausfuehrung:

- Dateien bleiben erhalten und koennen weiterverwendet werden
- Sie koennen beliebige Bibliotheken installieren
- Groessere Datenmengen sind moeglich
- Sie verstehen, was tatsaechlich auf Ihrem System passiert

Bisher hat das LLM den Code ausgefuehrt. Aber Sie wollen Code auch lokal ausfuehren koennen. Das gibt Ihnen mehr Kontrolle und ist noetig fuer komplexere Projekte.

3

Code kopieren und lokal ausfuehren

Bitten Sie das LLM um ein Skript zur Datenanalyse: 

Schreibe mir ein Python-Skript, das:
1. workshop_objekte.csv einliest
2. Die Anzahl Objekte pro objectClass zaehlt
3. Das Ergebnis als Tabelle ausgibt

Das Skript soll ich lokal ausfuehren koennen.
Erklaere jeden Schritt mit Kommentaren.

Das LLM wird ein Skript generieren. Kopieren Sie es in VS Code, speichern Sie es als analyse.py im selben Ordner wie die CSV-Datei.

Oeffnen Sie das Terminal in VS Code (Ctrl+` oder Menu: Terminal > New Terminal) und fuehren Sie aus: 

python analyse.py

Wenn Sie eine Fehlermeldung bekommen, kopieren Sie diese ins LLM und fragen Sie nach einer Loesung. Das ist der normale Workflow: Code generieren, ausfuehren, Fehler beheben, wiederholen.

So sollte die Ausgabe aussehen 
Workshop-Objekte Analyse
------------------------
Geladen: 25 Objekte

========================================
OBJEKTE NACH KATEGORIE
========================================
Kategorie                     Anzahl
----------------------------------------
Waffen                             8
Dokumente                          6
Werkzeuge                          5
Sonstiges                          6
----------------------------------------
GESAMT                            25
========================================

Haeufige Fehler

python: command not found - Python ist nicht im PATH. Unter Windows: Starten Sie VS Code neu oder fuehren Sie py analyse.py aus.

FileNotFoundError - Die CSV-Datei liegt nicht im selben Ordner. Verschieben Sie die Datei oder passen Sie den Pfad im Skript an.

ModuleNotFoundError: No module named 'pandas' - Falls das LLM pandas verwendet hat: pip install pandas im Terminal ausfuehren.

PE

Prompt Engineering

Der Prompt oben nutzt mehrere bewaehrte Techniken: nummerierte Schritte (macht die Struktur klar), explizites Ausgabeformat (Tabelle), Kontext (lokal ausfuehren) und die Bitte um Kommentare.

Diese Techniken sind keine Magie. Sie helfen dem LLM, Ihre Intention zu verstehen. Experimentieren Sie: Was passiert, wenn Sie die Kommentare weglassen?

Schulhoff et al. (2025). The Prompt Report. arXiv.

Checkpoint: Bereit fuer Teil 4?

  • Python laeuft lokal (python --version zeigt eine Versionsnummer)
  • Sie koennen ein Skript im Terminal ausfuehren
  • Sie wissen, wie Sie Fehlermeldungen ins LLM kopieren

Teil 4: Von CSV zu JSON

CSV ist gut fuer Tabellen, aber fuer Webseiten ist JSON praktischer. JSON kann hierarchische Strukturen darstellen und wird von JavaScript nativ unterstuetzt.

4

CSV zu JSON konvertieren

Lassen Sie ein Konvertierungsskript erstellen: 

Schreibe ein Python-Skript, das:
1. workshop_objekte.csv einliest
2. Jede Zeile als Objekt mit allen Spalten speichert
3. Das Ergebnis als workshop_objekte.json speichert

Format: Array von Objekten, UTF-8 Encoding, eingerueckt fuer Lesbarkeit.

Speichern Sie das Skript als csv_to_json.py und fuehren Sie es aus: 

python csv_to_json.py
So sollte die JSON-Datei aussehen

Oeffnen Sie workshop_objekte.json in VS Code. Die Struktur sollte so aussehen:

[
  {
    "pid": "o:hgk.1234",
    "title": "Revolver Lefaucheux",
    "objectClass": "Waffen",
    "dateText": "um 1870",
    "year": 1870,
    "description": "...",
    "qualityScore": 0.85
  },
  {
    "pid": "o:hgk.1235",
    ...
  }
]

Wichtig: Die Datei sollte mit [ beginnen und mit ] enden.

Sie sollten nun eine JSON-Datei im selben Ordner haben. Oeffnen Sie sie in VS Code und pruefen Sie die Struktur.

Teil 5: Die Webseite erstellen

Jetzt kommt der spannende Teil: Eine Webseite, die Ihre Daten anzeigt. Eine Webseite besteht aus HTML (Struktur), CSS (Design) und JavaScript (Interaktivitaet).

5

HTML-Grundgeruest erstellen

Geben Sie dem LLM einen strukturierten Prompt: 

Erstelle eine einfache Webseite fuer Museumsobjekte.

Datenquelle: workshop_objekte.json (liegt im selben Ordner)

Anforderungen:
- Zeige alle Objekte als Karten (Cards)
- Jede Karte zeigt: Titel, objectClass, year, description
- Einfaches, sauberes Design
- Die JSON-Datei wird per fetch() geladen

Technologie: Vanilla HTML/CSS/JavaScript, keine Frameworks.

Gib mir drei Dateien: index.html, style.css, app.js

Erstellen Sie einen neuen Ordner (z.B. museum-web) und legen Sie die drei Dateien dort ab. Kopieren Sie auch die workshop_objekte.json in diesen Ordner.

Ordnerstruktur
museum-web/
  index.html
  style.css
  app.js
  workshop_objekte.json

Um die Webseite zu testen, brauchen Sie einen lokalen Server. Der Browser blockiert das Laden lokaler Dateien aus Sicherheitsgruenden (CORS).

Installieren Sie die Live Server Extension in VS Code:

  1. Oeffnen Sie die Extensions-Seitenleiste (Ctrl+Shift+X)
  2. Suchen Sie nach "Live Server"
  3. Installieren Sie die Extension von Ritwick Dey
  4. Rechtsklick auf index.html > "Open with Live Server"
So sollte die Webseite aussehen

Im Browser sollten Sie sehen:

- Eine Ueberschrift mit dem Seitentitel
- 25 Karten, eine pro Objekt
- Jede Karte zeigt Titel, Kategorie-Tag, Jahr-Tag, Beschreibung
- Beim Hover aendern die Karten leicht ihre Darstellung

Falls nichts angezeigt wird: Oeffnen Sie die Browser-Konsole (F12 > Console) und pruefen Sie auf Fehlermeldungen.

Haeufige Fehler

Failed to fetch oder CORS error - Sie haben die Datei direkt geoeffnet (file://) statt ueber Live Server. Rechtsklick > Open with Live Server.

404 Not Found - Die JSON-Datei liegt nicht im richtigen Ordner. Pruefen Sie, ob workshop_objekte.json neben index.html liegt.

Leere Seite ohne Fehler - Pruefen Sie den Dateinamen in app.js. Heisst die Datei genau workshop_objekte.json?

CL

Code Literacy

Sie muessen den generierten Code nicht Zeile fuer Zeile verstehen. Aber Sie sollten die Grundstruktur erkennen: HTML definiert was angezeigt wird, CSS wie es aussieht, JavaScript was passiert.

Suchen Sie in app.js nach fetch - das ist der Teil, der die JSON-Datei laedt. Suchen Sie nach einer Schleife (for oder forEach) - das ist der Teil, der durch alle Objekte geht.

Lopez et al. (2008). Reading vs Writing Code. ITICSE.

Checkpoint: Bereit fuer Teil 6?

  • Die Webseite zeigt alle 25 Objekte als Karten
  • Live Server laeuft (URL beginnt mit http://localhost)
  • Keine Fehler in der Browser-Konsole

Teil 6: Iterativ verbessern

Die erste Version funktioniert, aber Sie wollen mehr. Vielleicht eine Filterung nach objectClass? Eine Sortierung nach Jahr? Das ist der Normalfall: Sie starten einfach und erweitern schrittweise.

6

Filter hinzufuegen

Erweitern Sie die Webseite um ein Kategorie-Filter: 

Erweitere die Webseite um einen Filter:

Aktuelle Situation:
- Alle Objekte werden als Karten angezeigt
- Es gibt verschiedene objectClass-Werte

Gewuenschte Erweiterung:
- Dropdown-Menu mit allen objectClass-Werten
- Option "Alle" zeigt alle Objekte
- Auswahl eines Werts filtert die Anzeige

Aendere nur die notwendigen Stellen in app.js und index.html.

Beachten Sie, wie der Prompt die aktuelle Situation beschreibt. Das hilft dem LLM, den Kontext zu verstehen und gezielt zu aendern statt alles neu zu schreiben.

So sollte der Filter funktionieren

Nach der Aenderung sollten Sie sehen:

1. Ein Dropdown-Menu oberhalb der Karten
2. Optionen: "Alle anzeigen", "Waffen", "Dokumente", "Werkzeuge", ...
3. Bei Auswahl einer Kategorie: Nur passende Karten werden angezeigt
4. Anzeige der Anzahl: "8 Objekte" statt "25 Objekte"

Testen Sie: Waehlen Sie "Waffen", dann "Alle anzeigen". Die Anzahl sollte sich entsprechend aendern.

Die Loesung erfordert Aenderungen in zwei Dateien:

In index.html kommt ein neues Element hinzu: 

<div class="filter-container">
  <label for="kategorie-filter">Kategorie:</label>
  <select id="kategorie-filter">
    <option value="">Alle anzeigen</option>
  </select>
</div>

In app.js brauchen Sie zwei neue Funktionen: Eine zum Befuellen des Dropdowns mit den verfuegbaren Kategorien, eine zum Filtern bei Auswahl.

RV

Review

Nach jeder Aenderung: Testen! Funktioniert der Filter? Zeigt "Alle" wirklich alle Objekte? Was passiert bei objectClass-Werten mit Sonderzeichen?

LLMs machen Fehler. Sie erfinden manchmal Funktionen, die nicht existieren (Halluzinationen). Sie uebersehen Grenzfaelle. Systematisches Testen ist nicht optional.

Tambon et al. (2024). Bug Patterns in LLM Code. TSE.

Was Sie gelernt haben

In diesem Tutorial haben Sie den kompletten Workflow erlebt:

  • Daten mit dem LLM explorieren und verstehen
  • Python-Code lokal ausfuehren
  • Datenformate konvertieren (CSV zu JSON)
  • Eine Webseite mit HTML/CSS/JavaScript erstellen
  • Iterativ erweitern und verbessern

Das ist die Essenz von AI Coding Literacy: Sie muessen nicht programmieren koennen. Aber Sie muessen wissen, wie Sie mit dem LLM kommunizieren, wie Sie Ergebnisse pruefen und wie Sie iterativ verbessern.
