Workshop Tutorial

Datenverarbeitung mit API

Bereinigen, anreichern, strukturieren

In diesem Tutorial lernen Sie, wie Sie die LLM-API programmatisch nutzen. Statt einzelner Chat-Nachrichten verarbeiten Sie Daten automatisiert. Das eroeffnet neue Moeglichkeiten: Batch-Verarbeitung, Datenanreicherung, Konvertierung von unstrukturierten zu strukturierten Daten.

Loesung: api_test.py Loesung: batch_extract.py

Warum die API?

Im ersten Tutorial haben Sie das LLM ueber das Chat-Interface genutzt. Das funktioniert gut fuer einzelne Aufgaben. Aber was, wenn Sie 100 Beschreibungen verarbeiten wollen? Oder 1000? Manuelles Copy-Paste ist keine Option.

Die API (Application Programming Interface) erlaubt es, das LLM aus Ihrem Code heraus anzusprechen. Sie schreiben ein Python-Skript, das automatisch Anfragen an das LLM schickt und die Antworten verarbeitet.

CE

Context Engineering

Bei API-Aufrufen ist Context Engineering noch wichtiger als im Chat. Sie haben keinen Dialog: eine Anfrage, eine Antwort. Der gesamte Kontext muss im Prompt sein.

Die bewaehrte Struktur: Rolle, Aufgabe, Informationen, Constraints, Ausgabeformat. Bei strukturierten Ausgaben wie JSON: Exakt spezifizieren, was Sie erwarten.

Mei et al. (2025). A Survey of Context Engineering. arXiv.

Teil 1: API-Zugang einrichten

Fuer dieses Tutorial verwenden wir die Claude API von Anthropic. Sie brauchen einen API-Key. Dieser identifiziert Sie gegenueber dem Dienst und ermoeglicht die Abrechnung.

1

API-Key erhalten

Gehen Sie zu console.anthropic.com, erstellen Sie ein Konto und generieren Sie einen API-Key. Fuer Workshops stellen wir oft einen temporaeren Key bereit.

Der API-Key ist wie ein Passwort: Teilen Sie ihn nicht, committen Sie ihn nicht in Versionskontrolle. Speichern Sie ihn in einer Umgebungsvariable oder einer lokalen Konfigurationsdatei.

2

Bibliothek installieren

Oeffnen Sie das Terminal und installieren Sie die anthropic-Bibliothek: 

pip install anthropic
So sollte die Ausgabe aussehen 
Successfully installed anthropic-0.x.x

Falls Sie eine Meldung sehen wie "Requirement already satisfied", ist die Bibliothek bereits installiert.

Haeufige Fehler

pip: command not found - Versuchen Sie pip3 install anthropic oder unter Windows: py -m pip install anthropic

Permission denied - Verwenden Sie pip install --user anthropic oder starten Sie das Terminal als Administrator.

Teil 2: Der erste API-Aufruf

Beginnen wir mit einem einfachen Beispiel. Das folgende Skript schickt eine Anfrage an Claude und gibt die Antwort aus. 

import anthropic

# API-Client erstellen
client = anthropic.Anthropic(
    api_key="Ihr-API-Key-hier"  # Oder: aus Umgebungsvariable
)

# Nachricht senden
message = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "Was ist ein Museum?"}
    ]
)

# Antwort ausgeben
print(message.content[0].text)

Speichern Sie diesen Code als api_test.py, ersetzen Sie den API-Key und fuehren Sie aus: python api_test.py

So sollte die Ausgabe aussehen

Sie sollten eine Antwort wie diese sehen:

Ein Museum ist eine Institution, die Objekte von kultureller,
historischer, wissenschaftlicher oder kuenstlerischer Bedeutung
sammelt, bewahrt, erforscht und der Oeffentlichkeit zugaenglich
macht...

Die genaue Formulierung variiert bei jedem Aufruf.

Haeufige Fehler

AuthenticationError - Der API-Key ist falsch oder fehlt. Pruefen Sie Tippfehler und ob der Key aktiv ist.

ModuleNotFoundError: anthropic - Die Bibliothek ist nicht installiert. Fuehren Sie pip install anthropic aus.

RateLimitError - Sie haben zu viele Anfragen gesendet. Warten Sie einige Sekunden und versuchen Sie es erneut.

Wenn alles funktioniert, sehen Sie eine Antwort von Claude. Wenn nicht, pruefen Sie die Fehlermeldung oben.

PE

Prompt Engineering

Bei API-Aufrufen koennen Sie den system-Parameter nutzen, um dem LLM eine Rolle oder Grundhaltung zu geben. Das ist wie eine Vorabinstruktion, die bei jedem Aufruf gilt.

Beispiel: system="Du bist ein Experte fuer Museumskataloge. Antworte praezise und faktenbasiert."

Anthropic (2024). Prompt Engineering Guide.

Checkpoint: Bereit fuer Teil 3?

  • Die anthropic-Bibliothek ist installiert
  • Sie haben einen funktionierenden API-Key
  • Der erste API-Aufruf hat eine Antwort zurueckgegeben

Teil 3: Daten bereinigen

Jetzt wird es praktisch. Unsere Museumsdaten haben ein Problem: Das Feld description enthaelt semi-strukturierten Text mit Angaben zu Material, Masse, Herkunft. Wir wollen diese Informationen in separate Felder extrahieren.

3

Beschreibungen analysieren

Schauen Sie sich einige Beschreibungen an: 

# Beispiel-Beschreibungen aus dem Datensatz:

"Dolch mit Holzgriff. Material: Stahl, Holz. Masse: L. 25 cm."

"Revolver, System Smith & Wesson. 6-schüssig. Herkunft: USA."

"Handschellen aus Eisen. Gebrauchsspuren sichtbar."

Manche Beschreibungen haben explizite Feldangaben (Material:, Masse:), andere nicht. Das ist ein typisches Problem bei historischen Daten. Ein LLM kann hier helfen, weil es natuerliche Sprache versteht.

RE

Requirement Engineering

Bevor Sie Code schreiben: Was genau wollen Sie extrahieren? Welche Felder? Was, wenn eine Information fehlt? Was ist das Ausgabeformat?

Definieren Sie: Eingabe (Beschreibungstext), Ausgabe (JSON mit definierten Feldern), Verhalten bei fehlenden Informationen (null oder leerer String?), Umgang mit Mehrdeutigkeiten.

Vogelsang & Fischbach (2024). LLMs for RE Tasks. arXiv.

4

Extraktions-Prompt entwickeln

Formulieren Sie einen Prompt, der die gewuenschte Extraktion beschreibt: 

EXTRACTION_PROMPT = """
Extrahiere strukturierte Informationen aus dieser Museumsobjekt-Beschreibung.

Beschreibung: {description}

Extrahiere folgende Felder (falls vorhanden):
- material: Liste der Materialien
- dimensions: Masseangaben (als Text)
- origin: Herkunftsort oder -land
- condition: Zustandsbeschreibung

Ausgabe als JSON. Felder ohne Information: null.
Nur das JSON ausgeben, keine Erklaerung.

Beispiel-Ausgabe:
{{"material": ["Stahl", "Holz"], "dimensions": "L. 25 cm", "origin": null, "condition": null}}
"""

Beachten Sie das Beispiel am Ende. Das ist Few-Shot Prompting: Sie zeigen dem LLM das gewuenschte Format anhand eines Beispiels.

Teil 4: Batch-Verarbeitung

Jetzt kombinieren wir alles: Wir lesen die CSV-Datei, schicken jede Beschreibung an die API und speichern die extrahierten Daten. 

import anthropic
import pandas as pd
import json
import time

# Setup
client = anthropic.Anthropic(api_key="Ihr-Key")

# Daten laden
df = pd.read_csv("workshop_objekte.csv")

# Ergebnisse sammeln
results = []

for index, row in df.iterrows():
    print(f"Verarbeite {index + 1}/{len(df)}: {row['title'][:30]}...")

    # Prompt mit Beschreibung fuellen
    prompt = EXTRACTION_PROMPT.format(description=row['description'])

    try:
        message = client.messages.create(
            model="claude-sonnet-4-20250514",
            max_tokens=500,
            messages=[{"role": "user", "content": prompt}]
        )

        # JSON aus Antwort parsen
        response_text = message.content[0].text
        extracted = json.loads(response_text)
        extracted['pid'] = row['pid']  # ID hinzufuegen
        results.append(extracted)

    except Exception as e:
        print(f"  Fehler: {e}")
        results.append({'pid': row['pid'], 'error': str(e)})

    # Pause zwischen Anfragen (Rate Limiting)
    time.sleep(0.5)

# Ergebnisse speichern
output_df = pd.DataFrame(results)
output_df.to_csv("extrahierte_daten.csv", index=False)
print(f"Fertig! {len(results)} Objekte verarbeitet.")

Warum time.sleep?

APIs haben Rate Limits - Begrenzungen, wie viele Anfragen pro Sekunde erlaubt sind. Ohne Pause sendet Ihr Skript Anfragen so schnell wie moeglich. Das fuehrt zu RateLimitError und blockiert Sie temporaer.

0.5 Sekunden Pause ist ein sicherer Wert. Bei grossen Datenmengen koennen Sie auch mit kleineren Pausen experimentieren.

So sollte die Ausgabe aussehen 
Verarbeite 1/25: Revolver Lefaucheux...
Verarbeite 2/25: Einbruchswerkzeug...
Verarbeite 3/25: Handschellen...
...
Fertig! 25 Objekte verarbeitet.

Am Ende sollte eine Datei extrahierte_daten.csv existieren.

CL

Code Literacy

Dieses Skript hat mehr Struktur als die vorherigen. Erkennen Sie die Teile? Setup (Client erstellen, Daten laden), Hauptschleife (for-Loop durch alle Zeilen), Fehlerbehandlung (try-except), Ausgabe (DataFrame speichern).

Die Schleife for index, row in df.iterrows() geht durch jede Zeile des DataFrames. row['description'] greift auf die Spalte description zu.

Hermans, F. (2021). The Programmer's Brain. Manning.

Checkpoint: Bereit fuer Teil 5?

  • Das Batch-Skript laeuft ohne Fehler durch
  • Die Datei extrahierte_daten.csv wurde erstellt
  • Stichproben zeigen plausible Ergebnisse

Teil 5: Daten anreichern

Extraktion ist gut. Aber LLMs koennen mehr: Sie koennen Daten anreichern. Zum Beispiel: Kategorisierung, Zusammenfassungen, Uebersetzungen.

5

Kategorisierung hinzufuegen

Erweitern Sie den Prompt um eine Kategorisierung: 

ENRICHMENT_PROMPT = """
Analysiere dieses Museumsobjekt und ergaenze strukturierte Metadaten.

Titel: {title}
Kategorie: {objectClass}
Beschreibung: {description}

Ergaenze:
1. keywords: 3-5 relevante Schlagworte (deutsch)
2. era: Historische Epoche (z.B. "Kaiserzeit", "Zwischenkriegszeit")
3. significance: Einschaetzung der musealen Bedeutung (hoch/mittel/gering)
4. related_topics: 2-3 verwandte Themengebiete

Ausgabe als JSON. Nur das JSON, keine Erklaerung.
"""

Vorsicht: Diese Anreicherungen sind LLM-Einschaetzungen, keine Fakten. Sie koennen hilfreich sein fuer Recherche und Exploration, aber nicht als autoritativ gelten.

RV

Review

Bei automatisierter Verarbeitung ist Review besonders wichtig. Sie sehen nicht jede einzelne Antwort. Strategien: Stichproben pruefen, Plausibilitaetschecks einbauen, unerwartete Werte flaggen.

Was, wenn das LLM halluziniert? Bei 100 Objekten werden Sie nicht jede Antwort lesen. Pruefen Sie zumindest die ersten 10 und einige zufaellige Stichproben.

Liu et al. (2024). HalluCode Benchmark. arXiv.

Teil 6: Unstrukturiert zu strukturiert

Ein haeufiger Anwendungsfall: Sie haben Freitext und wollen strukturierte Daten. Das klassische Beispiel sind historische Karteikarten, die als Fliesstext vorliegen.

6

Karteikarten-Konvertierung

Stellen Sie sich vor, Sie haben diesen Freitext: 

# Beispiel: Historische Karteikarte als Fliesstext

karteikarte = """
Inv.Nr. 1923/45
Dolch mit Scheide, vermutlich osmanisch, 18. Jhd.
Klinge aus Damaststahl, Griff aus Elfenbein mit
Silberbeschlaegen. Scheide Leder mit Metallbeschlaegen.
L. 35 cm (mit Scheide 40 cm). Erworben 1923 aus
Privatsammlung Dr. Karl Mueller, Wien. Zustand gut,
leichte Korrosionsspuren an Beschlaegen.
"""

Der Prompt fuer die Strukturierung: 

STRUCTURE_PROMPT = """
Konvertiere diese historische Karteikarte in strukturierte Daten.

Karteikarte:
{text}

Extrahiere in folgendes Schema:
- inventory_number: Inventarnummer
- title: Kurztitel
- object_type: Objekttyp
- date_text: Datierungsangabe (Originaltext)
- date_start: Frueheste Datierung (Jahr)
- date_end: Spaeteste Datierung (Jahr)
- materials: Liste der Materialien
- techniques: Herstellungstechniken
- dimensions: Masseangaben
- provenance: Erwerbsgeschichte
- condition: Zustandsbeschreibung
- notes: Weitere Anmerkungen

Ausgabe als JSON. Unbekannte Felder: null.
Bei Datierungen wie "18. Jhd." schaetze: date_start=1700, date_end=1799.
"""

Diese Art der Konvertierung ist eine Staerke von LLMs. Sie verstehen Kontext, koennen mit Varianten umgehen und interpretieren implizite Informationen.

EW

Expertenwissen

Hier zeigt sich der Wert Ihres Fachwissens. Das LLM kennt "osmanisch" und "Damaststahl" - aber Sie wissen, ob die Interpretation plausibel ist. Ist "18. Jhd." fuer osmanische Dolche realistisch? Ist Elfenbein fuer diese Periode typisch?

Ihr Domaenenwissen ist der Pruefstein. Das LLM liefert, Sie validieren.

Dell'Acqua et al. (2023). Navigating the Jagged Frontier. HBS.

Teil 7: Robustheit verbessern

Produktiver Code braucht Fehlerbehandlung. Was, wenn die API nicht antwortet? Was, wenn das JSON ungueltig ist? Hier ein robusteres Skript: 

import anthropic
import pandas as pd
import json
import time
from typing import Optional

def extract_with_retry(client, prompt: str, max_retries: int = 3) -> Optional[dict]:
    """Extrahiert Daten mit Wiederholungsversuchen bei Fehlern."""

    for attempt in range(max_retries):
        try:
            message = client.messages.create(
                model="claude-sonnet-4-20250514",
                max_tokens=500,
                messages=[{"role": "user", "content": prompt}]
            )

            response_text = message.content[0].text

            # Versuche JSON zu parsen
            # Manchmal gibt das LLM Markdown-Bloecke zurueck
            if response_text.startswith("```"):
                response_text = response_text.split("```")[1]
                if response_text.startswith("json"):
                    response_text = response_text[4:]

            return json.loads(response_text.strip())

        except json.JSONDecodeError as e:
            print(f"  JSON-Fehler (Versuch {attempt + 1}): {e}")
            time.sleep(1)

        except anthropic.RateLimitError:
            print(f"  Rate Limit erreicht, warte 30 Sekunden...")
            time.sleep(30)

        except Exception as e:
            print(f"  Fehler (Versuch {attempt + 1}): {e}")
            time.sleep(2)

    return None  # Alle Versuche fehlgeschlagen

Diese Funktion versucht es bis zu 3 mal, behandelt Rate Limits und bereinigt das JSON. Das macht den Unterschied zwischen einem Demo-Skript und einem nutzbaren Werkzeug.

Was Sie gelernt haben

In diesem Tutorial haben Sie den Sprung vom Chat-Interface zur programmatischen Nutzung gemacht:

  • API-Zugang einrichten und erste Anfragen stellen
  • Batch-Verarbeitung: Viele Datensaetze automatisiert verarbeiten
  • Strukturierte Extraktion aus unstrukturiertem Text
  • Datenanreicherung mit LLM-generierten Metadaten
  • Robuste Fehlerbehandlung fuer produktiven Einsatz

Die API eroeffnet Moeglichkeiten, die im Chat-Interface nicht praktikabel waeren. Aber sie erfordert auch mehr Sorgfalt: kein Dialog, keine Rueckfragen, systematische Pruefung der Ergebnisse.

Der naechste Schritt waere die Integration in bestehende Workflows: automatische Verarbeitung von Neuzugaengen, regelmaessige Datenanreicherung, Export in Dokumentationssysteme. Das sind keine Projekte fuer einen Workshop-Tag, aber die Grundlagen haben Sie jetzt.
